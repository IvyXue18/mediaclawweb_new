# 新官网 + 新插件发布联调用例矩阵

验证目标：新版插件与新版官网同时发布时，插件继续使用稳定 API，官网继续使用稳定域名，并覆盖不同用户状态、激活码、福利、支付、返佣和伙伴后台边界。

本地映射：

- 官网：`https://mediaclaw.app` -> `http://127.0.0.1:3002`
- 插件 API：`https://api.mediaclaw.app` -> `http://127.0.0.1:3005`

## 本轮自动化命令

```bash
pnpm test:phase1
pnpm test:phase2
pnpm test:p1
MEDIACLAW_E2E_BASE_URL=http://127.0.0.1:3002 pnpm exec playwright test tests/e2e/site-smoke.spec.ts tests/e2e/protected-routes-smoke.spec.ts tests/e2e/zpay-checkout.spec.ts
pnpm run build
```

插件联调：

```bash
bash scripts/package-extension.sh http://127.0.0.1:3005 http://127.0.0.1:3002 official
```

然后用 Playwright Chromium 加载 `dist/extension-release/mediaclaw`，检查侧边栏首屏、控制台错误、4xx 和 failed request。

### 本轮修正

- 本地 SQLite 缺 `referral_relation`，导致真实登录态 `/api/referral` 失败；已执行 `pnpm db:push` 同步测试库。
- 插件测试旧断言仍要求福利伙伴入口包含 `/partners`；已更新为 `/referral`，修正后插件完整 E2E 78/78 通过。
- 新插件本地包已确认 Web base 为 `http://127.0.0.1:3002`，API base 为 `http://127.0.0.1:3005`，普通伙伴计划入口为 `/referral`。

### 仍需处理/关注

- `/api/welfare/feedback` 当前返回 `not_migrated`，如果插件生产体验反馈奖励要走这个新官网后端接口，则该功能还未完全迁移。
- 登录态页面曾在浏览器自动化里出现 Header hydration mismatch：SSR 先渲染登录按钮，客户端 session 恢复后变用户菜单。推荐发布前修掉，避免首屏闪动和控制台噪音。
