## 推荐切流方案

### 方案 A：PostgreSQL/Hyperdrive 生产候选

推荐作为主线。

1. MediaClaw 专用 Hyperdrive 已创建并连接 Neon。
2. 当前本地部署配置已改为 `mediaclawweb-prod-candidate`，并配置 `mediaclaw.app` / `www.mediaclaw.app` routes。
3. `DATABASE_PROVIDER=postgresql` 已烘进候选 Worker 构建，`HYPERDRIVE` 作为运行时连接；`AUTH_SECRET` / `CONFIG_ENCRYPTION_KEY` / Zpay / License token 仍需走 Wrangler secrets。
4. 已部署到正式域名并完成只读公开页和基础 API 验证；下一步用受控账号测试登录、领奖、激活码配置、积分流水。
5. PostgreSQL 兼容 SQL 已 review、dry-run 并 COMMIT 执行，只做 additive / backfill。
6. 正式域名部署后继续复测登录、领奖、激活码配置、积分流水、支付回调、分销和工单等路径。

优点：最大程度保留旧站生产数据和登录/订单/积分连续性。缺点：必须处理 schema 兼容。

### 方案 B：迁旧 Postgres 到新 D1

不推荐作为第一选择。

需要导出旧 Postgres、做类型转换、处理外键/索引/时间戳/JSON、暂停写入或建立短期冻结窗口，并验证支付/积分/激活码一致性。当前已有真实订单和积分数据，直接迁 D1 的风险高于 Hyperdrive 承接。
