接入 Agent 后，不必把所有内容都搬进同一个系统。更稳定的做法是让 MediaClaw 保存平台证据与研究资产，让你的本地知识库保存自有事实和长期经验，再由 Agent 在任务中按需读取和组合。

## 三种接入方式

### 方式 1：直接读取 MediaClaw 资产

适合已经在数据池或 AI 工作台中的内容。Agent 会先列出匹配的采集记录、账号分析、单篇拆解、账号风格、选题或生成内容，再读取完整对象。这样可以保留结构和来源，也能避免重复采集。

### 方式 2：导出到本地知识库

适合长期归档、跨项目使用或与自有文档放在一起。

1. 在数据池筛选目标记录。
2. [导出 Markdown 或 CSV](/docs/collect/export-local)。
3. 把文件放入 Agent 客户端已授权读取的项目目录或知识库目录。
4. 按项目、平台、账号或主题建立稳定文件夹，不要每次临时散落在下载目录。
5. 在 Agent 任务中明确知识库目录和本次允许使用的范围。

### 方式 3：同步飞书供团队协作

适合多人补充状态、负责人、人工判断与复盘数据。MediaClaw 负责把结构化数据同步到飞书；Agent 是否能直接读取飞书，取决于当前 Agent 客户端是否另行获得飞书连接和授权。没有飞书连接时，可以从飞书导出本次需要的视图再交给 Agent。

## 推荐的知识库结构

```plaintext
content-knowledge/
├── 00-brand/            # 品牌定位、产品事实、禁用表述
├── 01-audience/         # 用户画像、访谈、常见问题
├── 02-platform-data/    # MediaClaw 导出的原始数据与样本
├── 03-research/         # 账号研究、单篇拆解、趋势结论
├── 04-topics/           # 选题卡、排期与状态
├── 05-drafts/           # 创作简报、稿件和版本
└── 06-published/        # 发布链接、表现数据与复盘
```

文件夹名不是强制规范，关键是把“外部证据、自有事实、分析判断、创作结果”分开，便于 Agent 判断每段内容的可信度和用途。

## Markdown 文件建议保留的头部

```yaml
asset_id: xhs-note-2026-001
asset_type: source_record
platform: xiaohongshu
source_url: https://www.xiaohongshu.com/explore/...
collected_at: 2026-08-15
project: creator-tools
topics: [内容研究, 创作效率]
rights: research-only
verified_at: 2026-08-15
```

正文中再分别放原文、数据、评论、分析和人工备注。不要删除原始链接，也不要把 Agent 的推断写成平台原始事实。

## 如何让 Agent 融合，而不是简单拼接

给任务时说明不同资产的角色：

- **MediaClaw 数据**用于证明平台上正在发生什么。
- **账号分析和单篇拆解**用于解释哪些内容机制反复出现。
- **品牌与产品资料**用于限定事实、价值主张和不能越过的边界。
- **历史稿件和复盘**用于判断你的表达习惯与过去真实效果。
- **本次人工输入**拥有最高的业务目标优先级，但不能覆盖客观事实。

示例：

```plaintext
先读取 MediaClaw 里与“个人知识库”相关的近期样本和已有单篇拆解，再读取 ./content-knowledge/00-brand 与 ./content-knowledge/06-published。请区分平台证据、我们自己的事实和你的推断，找出 3 个既有真实需求、又没有和历史内容重复的选题。每个选题标注证据来源；先不要写全文。
```

## 更新和失效管理

- 原始采集文件保留采集日期和来源，不覆盖成“最新事实”。
- 账号风格和选题规律按月或重要变化后复核。
- 产品能力、价格、政策和平台规则设置核验日期。
- 发布后把最终稿和表现数据写回，不要只保留生成初稿。
- 同一内容有多个版本时，明确草稿、已发布和已废弃状态。
- 删除或清理前先确认已有导出或同步副本，并保留来源索引。

## 隐私与权限

只授权 Agent 读取完成当前任务需要的目录。客户信息、未公开商业数据、账号凭证和第三方受限材料不要混入普通创作知识库。外部资料能否被某个 Agent 客户端读取，取决于该客户端的文件和连接权限，不由 MediaClaw 自动开放。

## 下一步

知识库整理完成后，可以回到[接入 Agent，结合知识库创作](/docs/create/agent-workflow)，让 Agent 先检查已有资产，再决定是否需要补充采集。
