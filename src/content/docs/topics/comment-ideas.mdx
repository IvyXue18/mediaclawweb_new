正文里没写清楚的问题，往往还留在评论区。先按[采集作品评论](/docs/collect/comments)把评论拿到手——这一步不重复说明；本页只讲拿到评论之后，怎么把它们变成选题。目前有三条方法，按你的工作方式选一条就够：单篇拆解自动归类、同步飞书模板跑 AI 分析、或者直接让 Agent 帮你读评论给选题。

<Callout type="tip">
  怎么选用哪种方法： - 只想深挖一篇代表作品、顺手要标题和大纲：方法一。 -
  想固定跑一批笔记、需要团队协作和留痕：方法二。 -
  想直接口述目标、不想在多个入口之间来回配置：方法三，前提是已完成 Agent
  接入配对。
</Callout>

## 方法一：单篇拆解自动归类评论区信号

<Callout type="note">
  这种方式，一次只分析一篇作品，并且由于重点是单条爆款的整体拆解，评论只是其中一块，最多含
  60 条，所以如果是专门做大量评论分析，可以跳过方法一，看后面两种。
</Callout>

1. 在作品卡片上点击拆解图标，进入[单篇拆解](/docs/viral-research/single-post-breakdown)，确认评论素材已经补全再开始拆解。

## 方法二：同步飞书模板，用AI字段捷径批量分析评论

<Callout type="note">
  这条方法适合批量分析多篇笔记，方便团队内部的协作分享，也方便复核。
</Callout>

1. 采集一批或一篇作品，附加采集评论；详情演示可查看👉[采集作品评论](/docs/collect/comments)。

3. 打开[飞书模板：功能与配置](/docs/settings/feishu-template)里**配置模板 AI 字段**一节，给**评论需求分析**字段配好自己的文本模型 Key，对整列评论跑一遍分析。模板自带的示例配置会给出需求归类、可延展的选题方向、以及选题依据引用的原评论——具体输出结构取决于你使用的提示词模板，最重要的是这块分析提示词可以自行调整。

## 方法三：结合 Agent 直接分析评论区

不需要先手动采集、同步表格、配置 AI 字段——完成[接入 Agent](/docs/agent/setup)配对后，把作品链接和你想要的结果直接描述给 Agent，它会调用插件的采集能力抓评论、按评论 ID 去重、归类需求，直接给出结论和候选选题，甚至完整的分析报告。

<DocImage
  src="/imgs/docs/topics/comment-ideas/04-Agent抓取评论并分析选题.webp"
  caption="在 Agent 里直接说明任务：抓取一条笔记至少 300 条评论，分析用户想法和需求，Agent 自动去重、归类并给出可切入的选题建议"
  captionEn="Describe the task directly to the Agent: fetch at least 300 comments from a note and analyze user needs — the Agent dedupes, categorizes the signals, and proposes candidate topics"
  width={1210}
  height={790}
/>

可以直接照抄这句话开始：

> 帮我打开这条笔记 &lt;作品链接&gt;，抓取至少 300 条评论，然后分析一下整个评论区的用户想法和需求，看看有没有我可以切入的选题。

Agent 会说明已处理和去重后的评论数量、核心判断、主要需求信号分类，最后给出可以优先切入的候选选题；你确认方向后，可以让它继续展开成完整标题和大纲。

**把整份报告存进本地知识库。** 如果你用 Obsidian、Logseq 这类本地 Markdown 笔记做长期积累，可以在分析跑完后补一句「把这份报告按 Markdown 存到我的 Obsidian 库 `<路径>`，文件名用笔记标题」。Agent 会把结论摘要、主题信号占比、代表性高赞评论、完整评论明细整理成一篇带大纲的笔记写到本地，之后可以离线检索、双链到相关选题，不必再回对话里翻。
