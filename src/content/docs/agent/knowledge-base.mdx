MediaClaw 知道平台上正在发生什么，你的知识库知道你是谁、你说过什么、你能兑现什么。**两个都在，Agent 才写得出别人写不出的东西。**

这一页解决怎么把后半边接上。你的情况大概率是两种之一：

- **已经有一套自己的笔记或知识库** → 看下面「把已有知识库接进来」。不需要重建目录、不需要加 frontmatter、不需要迁移。
- **还没有自己的知识库** → 跳到[三个文件起步](#三个文件起步)，教你搭建一个极简的个人知识库。

## 把已有知识库接进来

### 三条通道

| 通道                 | 适用                        | 特点                                 |
| -------------------- | --------------------------- | ------------------------------------ |
| **一、直接读文件夹** | 本地纯文本库                | 宿主的文件权限就够，零配置，最稳     |
| **二、装一个连接器** | 有开放 API 的，本地云端都行 | 能语义检索、能写回、跨设备           |
| **三、导出**         | 闭源、没有开放 API 的       | 导成 Markdown 放本地目录，退回通道一 |

### 按你在用的工具落位

## 三个文件起步

还没有知识库的话，别先去研究选型。**装 Obsidian，或者干脆就用一台电脑上的普通文件夹**——本地 Markdown 是 Agent 读写最顺的形态，云端笔记多一层导出或连接器，起步阶段没必要。

先放三样，当天就能用：

1. `我是谁.md`——做什么业务、服务谁、能说什么、不能承诺什么。十行就够。
2. 你还可以自行添加其他文件夹，比如产品业务背景，参考文档等等。
3. 一个装历史发布稿的文件夹。就是你的历史内容风格。
4. 一个空的 `研究/` 文件夹，让 Agent 往里写。

用出感觉之后再看本页末尾的[长期维护参考](#长期维护参考)。

## 五个真正用得上的场景

### 1. 不重复自己

```plaintext
先看 MediaClaw 里这个赛道近期的需求和评论信号，
再读 <历史发布稿目录>，找出平台上有人要、但我还没写过的选题。
已经写过的直接排除，写过但角度不同的单独列出来。
```

**没有本地文件会怎样**：MediaClaw 只能告诉你平台在发生什么，选题给出来了你才想起三个月前写过。
**有了之后**：交集才是选题。**这是最快能感受到价值的一条，建议从它开始。**

### 2. 补上 AI 编不出来的细节

拆完一篇爆款，结论可能是「这篇靠过程证明起效」。但你手上有没有能兑现的素材，MediaClaw 不知道。

```plaintext
按刚才的拆解结论，去 <客户案例目录> 和 <访谈目录> 里找我能用来兑现这个机制的真实素材。
找不到就直接告诉我缺什么，不要用通用例子代替。
```

**没有本地文件会怎样**：稿子写出来全是"很有共鸣""非常实用"这类空话——不是模型不行，是它没有事实可用。
**有了之后**：每个论点后面能挂上你自己的真实材料。

### 3. 对标自己，不只对标别人

```plaintext
采集我自己账号主页的作品表现数据，再读 <历史发布稿目录> 里每篇的写作说明，
找出我自己反复奏效的机制，以及表现差的那些共同缺了什么。
```

**没有本地文件会怎样**：只剩点赞数，看不出当时的意图和结果之间的关系。
**有了之后**：能分辨"这篇火是因为选题"还是"因为开头写法"。

### 4. 品牌口径守门

```plaintext
成稿前拿 <我是谁.md> 对一遍：有没有用到禁用表述、有没有承诺不能承诺的效果、
该带的资质说明有没有带。逐条告诉我改了什么。
```

**没有本地文件会怎样**：每个人写出来的口径都不一样，合规问题要靠人盯。
**有了之后**：一句话就能挡掉大部分问题，团队和乙方写稿时价值最大。

### 5. 把每次研究攒成自己的方法库

```plaintext
把这次分析按 Markdown 存到 <研究目录>，文件名用账号名加日期，
开头写清平台、账号、分析时间、样本量和主要缺口。
```

三个月后就可以问：「我研究过的账号里，哪些内容机制反复出现？」——Agent 读本地库就能回答，不用重跑采集、不花积分。

**没有本地文件会怎样**：每次研究都是一次性的，关掉对话就没了。
**有了之后**：一次性分析变成累积资产。**这条是长期留下来的理由。**

## 长期维护参考

用出感觉之后再看这一节，不必一开始就照做。

### 一种可用的目录结构

```plaintext
content-knowledge/
├── 00-brand/            # 品牌定位、产品事实、禁用表述
├── 01-audience/         # 用户画像、访谈、常见问题
├── 02-platform-data/    # MediaClaw 导出的原始数据与样本
├── 03-research/         # 账号研究、单篇拆解、趋势结论
├── 04-topics/           # 选题卡、排期与状态
├── 05-drafts/           # 创作简报、稿件和版本
└── 06-published/        # 发布链接、表现数据与复盘
```

文件夹名不重要，关键是把**外部证据、自有事实、分析判断、创作结果**分开，Agent 才能判断每段内容的可信度和用途。
