## 0. 2026-08-10 执行版：先处理停滞与下降页

本节是当前实施优先级的唯一依据，覆盖第 11、12 节中的旧排期。后文的信息架构、页面设计和内链规则继续有效。

### 0.1 决策规则

本轮不再按照“已有页面全部优化”安排工作，而是先按排名趋势分组：

1. **上涨页保护**：与上次周报相比，平均排名提升至少 1 位。暂不改 Title、Description、H1、URL 和主搜索意图，只允许增加事实性产品信息和来自新页面的自然内链。
2. **临界页增强**：排名变化在正负 1 位以内，但当前处于第 8-15 名，并且已有一定展现。优先补搜索意图、内容证据、FAQ、示例和内链；CTR 同时偏低时才调整标题与摘要。
3. **下降页增强**：平均排名下降至少 1 位，并且当前仍有可判断的展现。先查页面对应查询，再做定向增强，避免因为一次周报波动大改页面。
4. **低样本观察**：当前展现低于 20，或某一周期没有进入周报前 30 页，不依据单周数据直接改核心 SEO。先补齐 GSC 的 14/28 天页面与查询数据。

排名数值越小越好。下表中的“变化”使用“上次排名 → 本次排名”。本次比较来自 2026-08-03 与 2026-08-10 两次 SEO 周报。

> 数据限制：当前周报的页面表按点击排序且只保留前 30 页；报告脚本的两个比较周期也不是完全等长。因此，本节用排名方向安排工作，不把展示量变化当成严格实验结果，也不把“未进入前 30”直接判断为排名下跌。

### 0.7 稳定实施节奏

1. 每一批只增强 1-2 个现有页面，记录上线日期、改动的关键词/模块和内部链接。
2. 上涨保护页与正在增强的页面不得在同一批修改核心 TDK，避免无法判断影响来源。
3. 新页面按 N0 → N1 → N2 → N3 发布；先完成小红书 Hub 与账号分析页，再做抖音对应页。
4. 每个新页面发布前检查一次关键词互斥表；发布后记录 7/14/28 天收录、查询、排名、CTR 和转化。
5. 明确不同搜索意图的新页面可以继续制作，不需要等待 28 天；但相近关键词页面必须等前一页数据稳定后再发布。

第一轮实施完成条件：P0 五个现有页面完成定向增强，N0 两个新页面完成中英文内容、内链、结构化数据和搜索意图检查。完成后再根据最新数据确认 N1。

## 1. 本次重构的结论

MediaClaw 官网不再按照“采集、分析、生成、监控”等孤立功能组织页面，也不再使用功能集合式表达。

V0.2 的官网统一围绕一条完整的自媒体内容工作流展开：

> 发现内容方向 → 研究账号与爆款 → 沉淀选题和内容风格 → 生成图文或视频稿 → 持续追踪与复盘

页面架构采用“平台优先、搜索意图分层”的方式：

1. 小红书和抖音各有一个平台 Hub，承接平台级宽泛需求，解释完整工作流。
2. 账号分析、爆款分析、选题库按照平台分别建页，承接用户实际带平台名的搜索。
3. 关键词下拉词、对标账号发现、低粉爆款、一篇内容拆解、舆情扫描等能力不单独建 SEO 页面，而是进入最匹配的需求页，成为工作流步骤。
4. 已有采集、评论、逐字稿、监控、去水印页面保留 URL 和核心搜索意图，仅增加与上下游工作流的连接。

最终新增 8 个页面：

```text
/xiaohongshu
/douyin

/xiaohongshu/account-analysis
/douyin/account-analysis

/xiaohongshu/viral-content-analysis
/douyin/viral-content-analysis

/xiaohongshu/topic-library
/douyin/topic-library
```

不新增根目录下的 `/account-analysis`、`/viral-content-analysis` 或 `/content-idea-library`。用户搜索通常带有平台名称，现有官网架构也已经形成 `/xiaohongshu/*` 与 `/douyin/*` 两套平台路径，继续沿用更有利于搜索意图匹配、内部链接和后续扩展。

### 2.3 V0.2 新需求的早期信号

当前账号分析、选题、低粉爆款、舆情等新意图尚未形成很大的可见查询量，但已经出现精准搜索：

- Bing 查询 `能分析抖音和小红书账号的工具`：3 次展现、1 次点击、平均排名 2。
- 对标/竞品相关查询：GSC 4 次展现；Bing 11 次展现、5 次点击。
- 爆款相关查询：Bing 7 次展现、2 次点击。
- 选题相关查询：Bing 11 次展现、1 次点击，包含“小红书选题平台”“小红书找选题用哪个平台”等明确意图。
- 品牌舆情相关查询：Bing 2 次展现，尚无点击。

同时，已有内容页已经获得页面级曝光：

- 低粉爆款文章：GSC 合计约 245 次展现，但 0 点击。
- 选题库文章：GSC 合计约 62 次展现；Bing 10 次展现、1 次点击。
- 找对标账号文章：GSC 合计约 45 次展现，0 点击。
- 品牌舆情文章：GSC 仅 1 次展现。

因此，本轮不应把每一个 V0.2 功能都拆成独立页面。更合理的方式是把早期、相近意图组合成少数高完整度页面：

- “自动找对标账号”与“账号深度分析”组合为账号分析页。
- “低粉爆款发现”与“单篇/单条内容拆解”组合为爆款分析页。
- 关键词、评论、对标账号、爆款和舆情产生的内容方向统一沉淀到选题库页。
- 舆情扫描先作为“发现方向”和“持续复盘”的能力，不单独建页。

> 数据解释注意：GSC 会隐藏一部分低量查询，因此关键词页的页面展现明显高于公开查询行之和。页面级展现可证明该方向已被搜索，但不能据此虚构具体关键词的搜索量。

- URL：`/xiaohongshu/account-analysis`

- H1：`从找到小红书对标账号，到看清它为什么持续出爆款`

- 次关键词：小红书竞品账号分析、小红书账号数据分析、小红书博主分析
- 页面目的：承接“找谁学”和“这个账号为什么做得好”两个连续问题

#### 组合能力

1. 输入行业词、产品词或种子账号。
2. 自动发现相关对标账号。
3. 按头部、腰部、低粉高互动等条件筛选。

“不改”指不改变 URL 和主搜索意图；允许增加平台 Hub 入口、上下游内链和工作流说明。

---

## 8. 本轮不单独建页的能力

| 能力                  | 归属页面                         | 原因                                                     |
| --------------------- | -------------------------------- | -------------------------------------------------------- |
| 长尾关键词            | 平台关键词洞察页                 | 与搜索词挖掘同一意图                                     |
| 搜索下拉词            | 平台关键词洞察页                 | 无需制造薄页面                                           |
| 自动找对标账号        | 平台账号分析页                   | 发现与分析是连续任务                                     |
| 单篇笔记/单条视频拆解 | 平台爆款分析页                   | 与爆款发现共享样本和输出                                 |
| 低粉爆款              | 平台爆款分析页                   | 是筛选方式，不是独立最终目的                             |
| 舆情扫描              | 平台 Hub、评论页、选题库、监控页 | 当前搜索信号不足，且跨越发现与复盘阶段                   |
| 内容风格提炼          | 平台账号分析页与爆款分析页       | 风格来自账号/内容研究，不是孤立输入                      |
| 图片生成、视频生成    | 平台 Hub 的创作阶段              | 先表达完整研究到创作闭环，待搜索数据成熟后再决定是否独立 |

后续只有同时满足以下条件才考虑拆分独立页面：

1. GSC/Bing 出现持续、明确且与现有页面不同的查询簇。
2. 页面能提供独立输入、独立结果和独立转化目标。
3. 可以写出足够的平台专属内容，而不是复用同一套说明。
4. 拆分不会与现有页面产生关键词竞争。

## 9. 页面内容设计规范

### 9.1 所有新增页面统一回答六件事

1. 用户当前遇到的具体问题是什么。
2. MediaClaw 如何把多个能力串成一条工作流。
3. 用户需要提供什么输入。
4. 系统会完成哪些分析步骤。
5. 最终产出什么可继续使用的内容资产。
6. 下一步能进入哪个工作流节点。

### 9.2 页面不应出现的表达

- 连续堆叠十几个功能名称。
- “一站式”“全能”等没有证据的泛化口号。
- 只说 AI 分析，不展示输入、过程和输出。
- 把采集数据当作用户最终价值。
- 小红书与抖音只替换平台名称，案例和字段完全一致。
- 使用功能集合式定位作为导航名称或首屏文案。

### 9.3 建议使用的体系化表达

- `从搜索需求到可执行选题`
- `从对标账号到可复用的内容规律`
- `从爆款样本到系列化内容方向`
- `把研究结果沉淀成长期内容资产`
- `让每次发布的数据回到下一轮选题`
- `形成研究、选题、创作、复盘的完整闭环`

### 9.4 每页基础 SEO 要求

- 唯一的 Title、Description 和 H1。
- 中文与英文版本均有平台专属内容。
- 正确 canonical 与中英文 hreflang。
- BreadcrumbList 结构化数据。
- 产品/软件页根据实际内容增加 SoftwareApplication 或 WebApplication 数据。
- FAQ 只有在页面真实展示问答时才输出 FAQ 结构化数据。
- 至少 3 个正文上下文内链，不只依赖页脚。
- 图片 alt 描述实际界面或结果，不堆关键词。
- 新路由进入 sitemap、`llms.txt` 和 `llms-full.txt`。

## 10. 内部链接工作流

每个平台内部形成相同但内容不同的闭环：

```text
平台 Hub
  ↓
关键词洞察 ──→ 账号分析 ──→ 爆款分析
     │              │             │
     └──────────────┴─────────────┘
                    ↓
                  选题库
                    ↓
              图文/视频稿生成
                    ↓
          评论反馈 + 竞品监控复盘
                    ↓
                下一轮选题
```

具体规则：

1. 平台 Hub 链接全部核心页面。
2. 关键词页链接账号分析、爆款分析和选题库。
3. 账号分析页链接采集、爆款分析、选题库和监控。
4. 爆款分析页链接逐字稿/图文提取、评论和选题库。
5. 选题库页反向链接关键词、账号、爆款和评论页面，并进入创作流程。
6. 监控页链接账号分析和选题库，完成闭环。
7. 博客只链接与当前段落直接相关的产品页，避免统一堆在文末。

## 11. 分批执行计划

### 批次 A：下降与临界页

- 按第 0.3 节顺序完成 P0 五页，不触碰第 0.2 节上涨保护页的核心 SEO。
- 每页先导出查询级数据，再确定是补内容、补内链还是调整 TDK。
- 每批只发布 1-2 页，记录基线和上线日期。

交付：P0 页面变更记录、关键词映射、发布前后基线。

### 批次 B：小红书新入口

- 完成 `/xiaohongshu` 中英文 Hub。
- 完成 `/xiaohongshu/account-analysis` 中英文页面。
- 串联 scraper、keywords、comments、monitoring 与新增页，但不改上涨页主关键词。

交付：N0 两个新页面及内链网络。

### 批次 C：抖音新入口

- 复盘批次 A、B 的 7/14 天数据。
- 完成 `/douyin` 与 `/douyin/account-analysis`。
- 单独检查与 `douyin scraper`、`douyin profile viewer`、`douyin transcript` 的关键词冲突。

交付：N1 两个新页面及关键词互斥检查。

### 批次 D：爆款分析与选题库

- 先核对公开版本的深度分析、内容拆解与结果沉淀能力。
- 能力事实通过后发布两个爆款分析页。
- 选题需求和真实流程通过验证后，再发布两个选题库页。

交付：满足发布条件的 N2/N3 页面；不满足条件的页面继续保留草稿。

### 每批共同检查

- 更新 sitemap、canonical、hreflang、结构化数据、`llms.txt`、`llms-full.txt`。
- 检查中文与英文 Title/H1 唯一性和关键词互斥关系。
- 检查移动端、深色/浅色主题、首屏 CTA 和导航。
- 运行生产构建与关键路由访问测试。
- 发布后向 GSC 和 Bing 提交新 URL，并记录 7/14/28 天数据。

## 12. 优先级与延期规则

当前优先级以第 0 节为准：

1. **P0 现有页**：下降页和距第一页一步的停滞页。
2. **N0 新页面**：小红书 Hub 与小红书账号分析。
3. **P1 现有页**：下降但样本较小的抖音页面。
4. **N1 新页面**：抖音 Hub 与抖音账号分析。
5. **N2/N3 条件页**：爆款分析与选题库。

上涨页不因为 CTR 低或旧计划中曾列为优化对象而进入当前改版。若连续两个 14 天窗口排名停滞/下降，再从保护名单转入增强队列。

如果开发资源不足，不允许通过复制内容、减少平台差异或描述未上线能力来强行发布全部页面。未满足关键词与能力条件的页面保持草稿，避免产生薄页面和搜索意图内耗。

## 14. 上线后数据复盘

以页面上线日为基准，在第 7、14、28 天记录：

| 维度     | 观察指标                       | 判断动作                                        |
| -------- | ------------------------------ | ----------------------------------------------- |
| 收录     | GSC/Bing 是否发现并收录 URL    | 未收录则检查 sitemap、canonical、内链和抓取状态 |
| 查询匹配 | 页面开始获得哪些平台词和任务词 | 调整 Title/H1/首段，避免扩写无关词              |
| 排名     | 账号、爆款、选题簇的平均排名   | 11-20 名优先补案例、FAQ 和内链                  |
| CTR      | 展现增长后是否产生点击         | 高展现低点击优先改 Title 和 Description         |
| 转化     | CTA 点击、下载/使用行为        | 高流量低转化优先检查页面承诺与功能入口一致性    |
| 内耗     | 同一查询是否分散到多个页面     | 合并重复段落、调整锚文本或 canonical            |

是否继续拆分舆情、内容风格或生成类页面，只根据复盘后的真实查询簇与产品使用数据决定，不在本轮预先扩张 URL。

## 15. 本方案的一句话执行准则

> 先按平台承接用户搜索，再按完整工作流组织能力；每个页面解决一个明确任务，但让用户自然走向下一步。
