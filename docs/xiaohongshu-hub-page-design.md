> 状态：待评审，不进入开发

> 关联研究：[`research/platform-hub-keyword-research.md`](./research/platform-hub-keyword-research.md)
> 关联内链台账：[`internal-link-building-and-tracking.md`](./internal-link-building-and-tracking.md)

## 1. 先确定页面类型

小红书 Hub 仍然是一个由 sections/blocks 组合出来的普通营销页面，但不应硬塞进现有功能页 JSON 模板。

推荐实现：

- 新建一个可复用的 `PlatformHubPage` 页面类型。
- 页面由独立 Hub 区块组成，每个区块都可调整顺序、关闭或更换展示变体。
- 小红书、抖音和未来 TikTok 共用组件与数据结构，只替换平台内容、图片、功能顺序和 SEO 信息。
- 功能页继续使用现有功能页体系；Hub 不复制功能页长正文。

不建议继续把新 Hub 区块堆进 `legacy-dynamic-page.tsx`。该文件已经同时承担大量页面类型与渲染分支，继续扩大会让 Hub 变成另一个难维护的固定模板。

建议文件边界：

```text
src/
├── components/platform-hub/
│   ├── hub-hero.tsx
│   ├── hub-scene-navigator.tsx
│   ├── hub-feature-spotlight.tsx
│   ├── hub-feature-directory.tsx
│   ├── hub-workflow-showcase.tsx
│   ├── hub-outcome-gallery.tsx
│   └── hub-integration-card.tsx
├── blocks/platform-hub-page.tsx
├── content/platform-hubs/
│   ├── zh/xiaohongshu.json
│   └── en/xiaohongshu.json
└── routes/xiaohongshu/index.tsx
```

组件只负责展示；中文、英文内容和 URL 由 Hub 配置传入。路由负责 locale、canonical、hreflang 和结构化数据。

## 2. 页面目标与关键词边界

页面回答三个问题：

1. MediaClaw 在小红书上能帮我完成哪些目标？
2. 我现在应该进入哪个功能？
3. 从研究、采集到分析和复用，能力之间如何串起来？

页面不承担：

- 复制十个功能页的详细功能说明。
- 在 Hero 放教程入口。
- 创建必须经过的场景子页面。
- 用“小红书采集”“小红书图片下载”等强任务词替代对应功能页。

关键词方向：

| 语言 | Title 方向                                             | H1 方向                                |
| ---- | ------------------------------------------------------ | -------------------------------------- | --------------------------------------------------------------- |
| 中文 | `小红书数据采集与内容分析工具｜MediaClaw`              | `一站式完成小红书内容研究、采集与分析` |
| 英文 | `RedNote & Xiaohongshu Tools for Research and Analysis | MediaClaw`                             | `Research, collect and analyze RedNote content in one workflow` |

## 3. 页面整体结构

```text
Header
  ↓
Hub Hero：平台定位 + 我要使用 + 效果演示
  ↓
场景导航：我现在想先完成哪一步？
  ↓
重点功能：6 个最值得直接进入的功能
  ↓
闭环演示：搜索与筛选 → 采集样本 → 分析 → 选题/复用
  ↓
全部功能目录：4 个场景组、10 个功能页
  ↓
结果展示：数据、报告、选题、导出/飞书
  ↓
飞书集成：当前唯一已上线集成
  ↓
FAQ
  ↓
最终 CTA：我要使用
  ↓
Footer
```

用户不必按顺序浏览。Hero、场景导航、重点功能和完整目录都可以直接进入功能页；场景只负责在当前 Hub 内帮助选择，不增加跳转层级。

## 4. Section 设计与内容

### 4.1 `HubHero`

布局：

- 桌面端左右两栏，左 44%、右 56%。
- 移动端文案在上，静态产品画面在下。
- 不使用现有功能页 85vh 居中 Hero；Hub 首屏要在一个屏幕中同时露出定位、CTA 和真实产品画面。

中文内容：

- 眉题：`小红书内容工作流`
- H1：`一站式完成小红书内容研究、采集与分析`
- 描述：`从关键词和爆款中找到值得研究的账号与内容，批量采集公开笔记、评论和素材，再把逐字稿、图文文案、账号规律和可写选题沉淀下来。`
- 主按钮：`我要使用` → `/download`
- 次按钮：`效果演示` → 打开视频弹窗；视频未交付前不渲染
- 辅助说明：`Chrome 插件 · 无需代码 · 支持本地导出与飞书同步`

英文内容：

- 眉题：`RedNote & Xiaohongshu Content Workflow`
- H1：`Research, collect and analyze RedNote content in one workflow`
- 描述：`Find creators and posts worth studying, collect public content and comments, then turn transcripts, image text, account patterns and source-backed ideas into reusable research assets.`
- 主按钮：`Get Started`
- 次按钮：`Watch Demo`

Hero 不出现教程、文档、案例或“查看全部功能”按钮。“全部功能”通过首屏下方的场景导航自然露出。

Hero 画面：

- 使用真实界面组合，不生成虚构 UI。
- 主画面为干净的小红书搜索页 + MediaClaw 侧边栏。
- 右后方叠加账号分析报告、选题卡或采集结果的小幅预览，表达“浏览器页面 → 数据 → 报告/选题”。
- 静态画面作为视频 poster，点击播放仍由“效果演示”按钮触发，不让整张 Hero 图变成第二个隐形按钮。

### 4.2 `HubSceneNavigator`

标题：`你现在想先完成哪一步？`

描述：`按当前目标进入，不需要从头走完整套流程。`

四张场景卡：

| 场景             | 一句话内容                                     | 对应功能                       |
| ---------------- | ---------------------------------------------- | ------------------------------ |
| 找方向与研究样本 | 从关键词、近期爆款和对标账号中判断什么值得研究 | 关键词洞察、爆款分析、账号分析 |
| 采集数据与素材   | 把公开笔记、评论、主页作品和图片视频整理下来   | 笔记采集、评论采集、去水印下载 |
| 提取、洞察与转化 | 从图片、视频和评论中提取文案、需求与客户线索   | 图文文案、视频逐字稿、客资采集 |
| 持续跟踪与协作   | 监控对标账号变化，把结果同步给团队持续使用     | 竞品监控、飞书集成             |

交互：

- 点击场景卡只滚动到本页对应功能组并高亮，不进入新场景 URL。
- 键盘可操作，移动端为 2×2 卡片，不做难以发现的横向轮播。
- 四张卡片中的功能名使用真实文本链接，允许用户直接进入功能页。

### 4.3 `HubFeatureSpotlight`

标题：`小红书最值得直接进入的 6 个功能`

描述：`两项新内容研究能力，加上当前搜索需求最明确的采集、下载和文案提取入口。`

布局采用 2+4 Bento，而不是六张完全相同的卡片：

- 两张大卡：账号分析、爆款分析。
- 四张紧凑卡：笔记采集、去水印下载、图文文案提取、视频逐字稿。

卡片文案：

| 功能         | 卡片标题                       | 卡片描述                                                                         | 配图方向                    |
| ------------ | ------------------------------ | -------------------------------------------------------------------------------- | --------------------------- |
| 账号分析     | `拆清一个账号为什么持续有效`   | `从公开作品样本中比较定位、选题、标题、语言与视觉规律，并生成带来源的可写方向。` | 账号分析报告总览            |
| 爆款分析     | `看懂一篇爆款为什么有效`       | `把标题、正文、封面、图片文字、逐字稿与评论放进同一份证据化拆解。`               | 单篇拆解报告                |
| 笔记采集     | `批量整理笔记、主页与搜索结果` | `无需代码，把公开内容和互动字段保存成可筛选、可导出的研究样本。`                 | 小红书搜索页 + 插件采集结果 |
| 去水印下载   | `批量保存图片和视频素材`       | `按作品整理原图和视频，方便建立素材参考库。`                                     | 批量下载界面                |
| 图文文案提取 | `把图片里的文字一起提取出来`   | `识别封面和配图文字，回填到采集记录中。`                                         | OCR 前后结果                |
| 视频逐字稿   | `把口播视频转成可分析的逐字稿` | `同时获得完整文本和带时间戳的分句稿。`                                           | 逐字稿结果                  |

每张卡片整体可点击并直接进入功能页。大卡可以带图片；紧凑卡只放局部截图或图标，避免一屏出现六张难以阅读的产品截图。

### 4.4 `HubWorkflowShowcase`

标题：`把一次小红书内容研究跑成完整闭环`

说明：`MediaClaw 不要求你一次使用全部功能，但同一份数据可以从发现、采集继续进入分析、选题和复用。`

使用三组 Tab，每组都包含真实产品画面、简短说明和功能页上下文链接：

#### Tab 1：发现并采集值得研究的样本

- 文案：`搜索一个赛道或需求词，先按时间和互动表现筛出近期强内容，再把单篇笔记、账号主页或搜索结果整理为研究样本。`
- 链接：小红书关键词洞察、爆款分析、笔记采集。
- 画面：干净版小红书搜索页 + 插件搜索页采集面板。

#### Tab 2：从样本得到账号和内容结论

- 文案：`对账号做分层取样，对单篇内容保留标题、封面、正文、逐字稿和评论证据，避免只看点赞数下结论。`
- 链接：小红书账号分析、爆款分析、图文文案、视频逐字稿。
- 画面：账号报告 + 单篇拆解报告。

#### Tab 3：把结论变成选题并沉淀下来

- 文案：`将研究结论扩展成可写选题，进入内容创作，或把原始数据和结果导出到本地、同步到飞书继续协作。`
- 链接：关键词洞察、飞书集成；教程只有发布后才插入具体动作文字。
- 画面：选题卡 + 创作结果 + 飞书看板。

Tab 内容全部服务用户理解，不自动播放多个视频。桌面端切换画面，移动端改为连续三段，保证内容和链接都在 HTML 中可发现。

### 4.5 `HubFeatureDirectory`

标题：`全部小红书功能`

描述：`按任务选择入口；点击后直接进入对应功能页面。`

完整目录：

| 分组             | 功能         | 一句话说明                                     |
| ---------------- | ------------ | ---------------------------------------------- |
| 找方向与研究样本 | 关键词洞察   | 从主词判断趋势、扩展长尾并发现对标样本         |
|                  | 爆款分析     | 筛选强内容并拆解标题、封面、正文、评论与逐字稿 |
|                  | 账号分析     | 用公开作品样本研究账号定位、选题和表达规律     |
| 采集数据与素材   | 笔记采集     | 采集单篇、主页和关键词搜索结果                 |
|                  | 评论采集     | 批量整理评论并导出 Excel/CSV                   |
|                  | 去水印下载   | 批量保存作品图片和视频                         |
| 提取、洞察与转化 | 图文文案提取 | OCR 识别封面和配图文字                         |
|                  | 视频逐字稿   | 提取完整逐字稿与时间戳分句                     |
|                  | 客资采集     | 从评论中筛选高意向需求和线索                   |
| 持续跟踪         | 竞品监控     | 跟踪对标账号内容更新和互动变化                 |

布局：桌面端四组分栏，移动端 Accordion。即使折叠，服务端渲染 HTML 仍包含全部真实链接和文本。

功能目录不放大截图；它的职责是完整发现和内链覆盖，不能与上方重点卡片争夺视觉注意力。

### 4.6 `HubOutcomeGallery`

标题：`最后留下的不只是一堆散数据`

四种结果：

1. `可筛选的数据样本`：笔记、账号、评论和互动字段保持来源关系。
2. `有证据的研究报告`：账号分析和单篇拆解结论可回到原始作品。
3. `可以继续执行的选题与初稿`：研究结果进入选题库和内容创作。
4. `可复用的团队资产`：CSV、Excel、Markdown 或飞书多维表格。

布局：一张主画面配四个结果切换按钮，避免四张大截图把页面拉得过长。

建议画面：

- 数据样本：小红书搜索结果采集或插件列表。
- 研究报告：`account-report.webp`。
- 选题/初稿：`topic-card.webp`、`draft-result.webp`。
- 团队资产：`feishu-dashboard.webp`。

### 4.7 `HubIntegrationCard`

首版只展示飞书，不展示尚未发布的 Codex、WorkBuddy、TraeWork 等集成卡片，也不创建空链接。

- 眉题：`协作与集成`
- 标题：`把小红书研究结果同步到飞书继续使用`
- 描述：`将采集数据、评论、账号样本和研究结果同步到飞书多维表格，方便团队筛选、补充和持续积累。`
- 链接：`查看飞书集成` → `/features/feishu-integration`
- CTA 层级：普通文字/描边链接，不与“我要使用”竞争。

未来 Agent 集成上线时，该区块允许从单卡切换为多卡网格，但只有真实页面和能力发布后才渲染。

首版问题：

### 5.2 不建议直接用作 Hub Hero 的素材

- 2026-04-24 的完整总演示视频：可访问，但约 38 MB，界面和录屏时间较早，且完整视频过长。
- 带红框、红箭头和操作标注的 Docs 截图：适合教程，不适合营销首屏。

- AI 生成的抽象“小红书运营”插画：无法证明真实产品能力，不建议使用。

### 5.3 必须新增的素材

#### A. Hero 静态主图

建议尺寸：`1600 × 1100` 或同等比例 WebP。

画面组成：

1. 干净的小红书搜索结果页面，不带教程标注。
2. MediaClaw 小红书搜索页侧边栏。
3. 账号报告或选题卡的小幅叠层。
4. 使用官网现有紫红品牌光晕做背景层，不修改真实产品 UI。

该图由真实截图排版合成，不需要 AI 生成。

#### B. 小红书 Hub 效果演示

建议时长：38–45 秒；16:9；1080p；无真人口播也能看懂。

分镜：

| 时间     | 画面                                   | 屏幕字幕                     |
| -------- | -------------------------------------- | ---------------------------- |
| 0–5 秒   | 在小红书搜索一个赛道词并打开 MediaClaw | `从一个关键词开始`           |
| 5–11 秒  | 筛选近期强内容/低粉高互动样本          | `先找到值得研究的内容`       |
| 11–17 秒 | 批量采集搜索结果或账号作品             | `把公开样本整理下来`         |
| 17–25 秒 | 打开单篇爆款或账号分析报告             | `看懂内容和账号为什么有效`   |
| 25–33 秒 | 查看逐字稿、图文文案、评论信号         | `补齐文字、口播和评论证据`   |
| 33–40 秒 | 进入选题库/初稿或同步飞书              | `把结论变成可继续使用的资产` |
| 40–45 秒 | MediaClaw 品牌与下载提示               | `从你当前最需要的一步开始`   |

录制要求：

- 使用同一组测试关键词和同一批公开样本，前后画面能连成一条真实路径。
- 避免展示私人账号、激活码、Cookie、手机号或内部测试信息。
- 录制后输出 MP4、WebM、poster WebP；页面只预加载 poster，不预加载完整视频。
- 视频弹窗播放；不在 Hero 静音自动播放，避免首屏性能和移动端流量问题。

## 6. 教程链接的插入规则

初版 Hub 不渲染教程入口，原因不是页面不需要教程，而是当前 Docs 注册表没有可供程序判断的正式发布状态。

开发 Hub 时建议先给 Docs 元数据增加：

```ts
publishState: 'draft' | 'reviewed' | 'published';
```

只有 `published` 页面可以进入 Hub。插入位置固定为：

- Workflow 某一步的说明末尾。
- Feature Directory 某个功能的“如何操作”补充链接。
- FAQ 对应问题答案末尾。

Hero、重点功能卡和最终 CTA 不放教程链接。

## 7. 内链与 SEO 设计

### 页面出链

- Hero：只到下载页。
- 重点功能：6 个功能页。
- 完整目录：10 个功能页全覆盖。
- Workflow：按上下文链接相关功能；已发布教程以后再加入。
- 集成：飞书集成页。
- 最终 CTA：下载页。

### 页面入链（页面上线时执行）

- 首页小红书入口。
- Header 小红书标题和“查看全部功能”。
- 十个小红书功能页面包屑。
- 功能页正文中的“小红书工具/完整工作流”上下文链接。
- Footer 小红书 Hub。

### 结构化数据

- `BreadcrumbList`：首页 → 小红书工具。
- `CollectionPage`：描述 Hub 是一组小红书工具的集合页。
- `ItemList`：列出十个真实功能 URL。
- FAQ 只有页面实际渲染对应内容时才输出 `FAQPage`。
- 不给 Hub 输出单一 `SoftwareApplication` 评分，避免把集合页当作一个具体功能页。

## 8. 交互与性能约束

- 首屏只加载一张 poster，不加载 MP4。
- 所有非首屏图片使用 WebP、明确宽高并 lazy-load。
- 重点卡片不使用 hover 才能发现的关键信息；移动端同样可见。
- Tab/Accordion 不应让链接依赖客户端运行后才出现在 DOM。
- 重点卡片整体可点击，但卡片内不嵌套第二个 `<a>`。
- 动效只使用轻微位移、透明度和 Tab 切换；遵守 `prefers-reduced-motion`。
- Hero 两个按钮最多；无视频时只保留 `我要使用`。

## 9. 埋点方案

| 事件                     | 触发位置         | 核心属性                                    |
| ------------------------ | ---------------- | ------------------------------------------- |
| `hub_primary_cta_click`  | Hero/最终 CTA    | locale、placement                           |
| `hub_demo_click`         | 效果演示         | locale、video_id                            |
| `hub_scene_click`        | 四个场景卡       | scene、locale                               |
| `hub_feature_impression` | 重点功能进入视口 | feature、position、locale                   |
| `hub_feature_click`      | 重点卡/完整目录  | feature、scene、placement、position、locale |
| `hub_workflow_tab`       | Workflow Tab     | step、locale                                |
| `hub_integration_click`  | 飞书集成         | integration、locale                         |

导航排序至少观察 28 天，结合 Hub 点击率、功能页下载转化和 GSC/Bing 搜索变化，不按一两天数据调整。

## 10. 组件复用与实施批次

### 批次 1：组件和静态内容

- 新建 `PlatformHubPage` 与 7 个 Hub 组件。
- 建立小红书中英文配置。
- 建立 `/xiaohongshu` 路由、metadata、canonical、hreflang 和 schema。
- 先用静态 poster；没有新视频时不显示“效果演示”。

### 批次 2：素材与演示

- 完成 Hero 静态主图。
- 录制、压缩并上传 38–45 秒 Hub 演示。
- 视频通过实际播放验收后再打开次按钮。

### 批次 3：站内接入

- Header 增加小红书 Hub 入口和重点功能排序。
- 十个功能页面包屑链接到 Hub。
- 首页、Footer、相关功能正文接入 Hub。
- 更新 sitemap、`llms.txt`、`llms-full.txt` 和埋点白名单。

### 批次 4：复用到抖音

- 复用同一组件和信息模型。
- 替换抖音文案、截图、视频、重点功能顺序和关键词。
- 不复制小红书产品画面或平台字段。

## 11. 评审时只需要确认的四个决定

1. 是否采用“左右分栏真实产品画面”的 Hero，而不是现有居中大标题模板。
2. 是否确认重点功能为：账号分析、爆款分析、笔记采集、去水印下载、图文文案提取、视频逐字稿。
3. 是否同意首版不展示任何教程链接，等 Docs 增加正式发布状态后再按步骤插入。
4. 是否同意新增一段 38–45 秒的小红书闭环演示，不直接把旧 4 分钟录屏放进 Hero。
