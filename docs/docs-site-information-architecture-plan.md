# MediaClaw /docs 文档站信息架构与两周实施基线

> 状态：已确认，作为后续两周实施基线
> 更新时间：2026-07-22
> 范围：官网 `/docs` 系统教程站
> 不包含：`/xiaohongshu/*`、`/douyin/*` 营销与 SEO 落地页重构

## 0. 文件用途与边界

本文件固定 `/docs` 教程站的主叙事、侧边栏、页面归属、URL 规则与两周实施顺序。后续实现如需调整结构，应先更新本文件，再修改路由和内容，避免边做边重新分类。

与现有方案的关系：

- [`v0.2-content-workflow-website-plan.md`](./v0.2-content-workflow-website-plan.md) 规划官网营销页、平台 Hub 和 SEO 页面。
- 本文件规划 `/docs` 操作教程、运营方法和产品参考。
- 营销页负责回答“为什么使用 MediaClaw”；`/docs` 负责回答“接下来怎么做、为什么这样做”。
- 两者可以互相深链，但不得复制整段教程正文，避免维护分叉和搜索意图互抢。

Agent 自动化整条流程目前只是北极星愿景，不是已上线功能：

- 只允许出现在文档首页或“产品理念与未来方向”概念页。
- 必须明确标注“未来方向 / 尚未上线”。
- 不进入侧边栏主流程，不建立操作教程，不出现可执行步骤或虚构截图。

## 1. 已确认的核心判断

### 1.1 文档只保留一个主叙事

文档站不再并列展示“按身份上手 / 按目的找 / 能力库”三棵树。侧边栏只回答一个问题：

> 用户下一步应该做什么？

唯一主叙事是：

> **内容生产主线：从内容样本到可复用的内容资产。**

默认阅读顺序：

```text
采集有效样本 → 建立对标 → 筛选并拆解爆款 → 扩展并沉淀选题 → 生成内容与二创 → 沉淀与复用
```

这是一条默认阅读路径，不是强制的产品操作顺序。返回用户仍可通过搜索、首页目的卡和“全部功能索引”直接进入任意原子能力页。

### 1.2 个人博主 / OPC 是主线来源，不是栏目名称

真实的个人博主 / OPC 路径作为主线依据，但侧边栏不命名为“个人博主路线”，避免让品牌用户误以为内容生产能力与自己无关。

身份关系固定为：

```text
博主 / OPC = 内容生产主线
品牌 / 企业 = 内容生产主线 + 舆情与线索分支
```

首页只需要两张身份提示卡；“选择阅读路线”只建立一张串联页，不为两类人群复制两套教程。

### 1.3 能力页仍然原子化，但不再展示独立能力树

- 每个已上线能力只有一个正文页面或一个明确的页内章节。
- 原子能力页直接挂在主线或品牌分支中。
- 其他场景页、串联页和营销页只提供上下文与深链，不复制操作说明。
- “全部功能索引”是扁平索引页，只列链接和产品位置，不拥有教程正文。

### 1.4 产品界面词汇作为定位信息，不统治整棵文档树

“AI 工作台 / 内容研究 / 选题库 / 内容创作”必须与产品界面完全一致，但它们主要用于：

- 页面眉题或“产品位置”字段；
- 面包屑和搜索过滤；
- “认识 AI 工作台”映射页；
- 功能索引中的产品位置列。

示例：

```text
账号研究
产品位置：AI 工作台 > 内容研究
```

对应关系：

| 产品位置             | 文档主线位置                                   |
| -------------------- | ---------------------------------------------- |
| AI 工作台 > 内容研究 | 建立对标、筛选并拆解爆款、扩展选题中的研究动作 |
| AI 工作台 > 选题库   | 扩展并沉淀选题                                 |
| AI 工作台 > 内容创作 | 生成内容与二创                                 |
| 插件采集区           | 采集有效样本                                   |
| 导出与飞书同步       | 沉淀与复用                                     |

### 1.5 导出与同步回到主线终点

导出、飞书同步虽然会被多个场景调用，但用户真实路径以“沉淀飞书、导入自己的 AI 知识库”结束。因此它们的唯一正文归属是主线第 6 段“沉淀与复用”，不再作为独立公共能力域与主线并列。

## 2. 页面类型与内容边界

实施时只使用以下五种页面类型。

| 类型   | 是否有独立 URL | 是否写完整操作           | 用途                             |
| ------ | -------------- | ------------------------ | -------------------------------- |
| 正文页 | 是             | 是                       | 一个能力的唯一教程正文           |
| 方法页 | 是             | 只写方法与判断，操作深链 | 组合多个能力完成一个目的         |
| 串联页 | 是             | 否                       | 说明阅读顺序、前置条件和下一步   |
| 映射页 | 是             | 否                       | 映射产品界面词与用户任务         |
| 索引页 | 是             | 否                       | 汇总能力链接、产品位置与适用人群 |

侧边栏分组不是页面，不要为了每层对称而创建空泛的“概览”。只有整条主线、快速闭环或品牌路线确实需要解释顺序时，才建立串联页。

### 2.1 每个正文页的统一模板

每个原子能力正文页至少包含：

1. **这页帮你完成什么**：一句话结果，不以按钮开头。
2. **适用场景与前置条件**：需要什么输入、什么情况下使用。
3. **运营者视角方法卡**：MediaClaw 替用户做了哪个判断、为什么这么判断。
4. **操作步骤**：界面位置、输入、动作和结果。
5. **如何理解输出**：字段、结果质量和下一步判断。
6. **限制与保护机制**：数量、频率、隐私、平台差异或失败边界。
7. **下一步**：主线上的上一步、下一步以及少量相关能力。

建议为内容注册表预留这些元数据：

```ts
type DocMeta = {
  title: string;
  navTitle?: string;
  description: string;
  pageType: 'guide' | 'method' | 'path' | 'mapping' | 'index';
  productLocation?: string;
  audiences?: Array<'creator' | 'opc' | 'brand'>;
  goals?: string[];
  order?: number;
  previous?: string;
  next?: string;
  related?: string[];
};
```

字段名称可在实现时按框架调整，但“页面类型、产品位置、适用人群、目标、前后步骤”必须可被程序读取，以便侧边栏、搜索、功能索引和相关推荐共用同一份元数据。

## 3. 最终侧边栏与 URL 基线

标记说明：

- `[正文]`：能力唯一正文页。
- `[方法]`：组合方法页，能力操作只深链。
- `[串联]`：阅读路线页，不复制教程。
- `[映射]`：产品词与任务词映射页。
- `[索引]`：扁平链接索引。
- `[页内]`：只做 H2/H3，不占侧边栏。
- `[分组]`：非点击侧边栏标题，不建页面。

### 3.1 不进入主侧边栏的入口

以下内容只允许出现在指定位置：

| 内容                           | 出现位置                         | 处理方式                         |
| ------------------------------ | -------------------------------- | -------------------------------- |
| 博主 / OPC 路线                | 首页身份卡、选择阅读路线         | 深链主线 1–6                     |
| 品牌 / 企业路线                | 首页身份卡、选择阅读路线         | 深链主线 1–6，再进入品牌分支     |
| 找选题、找对标、拆爆款等目的卡 | 文档首页                         | 深链对应分组的首个正文页或方法页 |
| 全部能力                       | 参考与帮助 > 全部功能索引        | 单页扁平列出，不建立可展开能力树 |
| Agent 自动化愿景               | 文档首页；必要时从首页链接概念页 | 明确未上线，不提供操作说明       |

### 3.2 侧边栏交互要求

- 桌面端默认只展开当前主线步骤，其他步骤折叠。
- 移动端使用抽屉，不同时展示侧边栏和正文目录。
- 左侧导航最多三层，不使用“镜头、能力域、原子能力”等内部 IA 术语。
- 正文页底部提供“上一步 / 下一步”，主线阅读不依赖返回侧边栏。
- 分组上的 `1–6` 只用于视觉顺序，slug、内容 ID 和 canonical URL 不带编号。
- 页面标题使用用户任务语言；产品位置单独显示，不把两套词硬拼进导航标题。

## 4. 唯一归属与深链清单

以下能力最容易被重复编写，实施时必须按本表治理。

| 能力                                      | 唯一正文或章节                        | 其他位置如何处理                                   |
| ----------------------------------------- | ------------------------------------- | -------------------------------------------------- |
| 评论采集                                  | `/docs/collect/comments`              | 舆情、线索页先解释用途，再深链采集步骤             |
| 创作风格                                  | 账号研究页内章节                      | 图文稿、视频稿和二创页只说明选择已有风格并深链     |
| 近 / 中 / 远 9 个延伸选题                 | 单篇爆款拆解页内章节                  | 批量扩展选题和选题库页只引用产物，不重复生成步骤   |
| 研究档案分享                              | `/docs/viral-research/share-research` | 账号研究、爆款拆解页只放分享入口与深链             |
| 单次 300 条、频率保护、自动去重、分批保存 | 批量采集页内章节                      | 不拆成版本功能页，不在各采集方式重复说明           |
| 超过 500 条自动分段分组同步               | 飞书同步页内章节                      | 其他页面只说明将进入分段同步并深链                 |
| CSV / Excel / Markdown 导出               | `/docs/reuse/export`                  | 客资交付、知识库方法页只说明需要的格式并深链       |
| 飞书多维表格同步                          | `/docs/reuse/feishu-base`             | 客资、选题、素材管理场景只深链                     |
| AI 知识库使用方法                         | `/docs/reuse/ai-knowledge-base`       | 只讲整理、分块、更新与使用方法；导出按钮深链导出页 |

“评论口碑与舆情扫描”和“评论区线索识别”可以分别拥有正文：前者判断群体观点和风险变化，后者识别具体潜客，不是同一能力。

“账号研究”和“监控对标账号”也必须分开：前者是一次性深度研究并产出规律或创作风格，后者是持续跟踪并产出更新与日报。

## 5. 文档首页基线

`/docs` 首页不是功能列表页，应按以下顺序建立主叙事：

1. **一句话定位**：把小红书、抖音内容样本变成可复用的选题、稿件和内容资产。
2. **能力阶梯**：Lv0 下载 → Lv1 结构化采集 → Lv2 判断 → Lv3 洞察 → Lv4 创作 / 喂 AI。
3. **内容生产主线**：六段流程图，每段只保留一个主 CTA。
4. **两类身份提示**：博主 / OPC 走主线；品牌 / 企业走主线并增加舆情与线索分支。
5. **按目的直达**：找选题、找对标、拆爆款、管理选题、二创、获客、舆情、喂 AI；只深链，不拥有教程。
6. **首次闭环 CTA**：进入“10 分钟从采集跑到初稿”。
7. **北极星愿景**：用 Agent 指挥整条流程；必须标注“未来方向，尚未上线”。

首页不展示完整能力墙，也不同时解释“按身份 / 按目的 / 按能力”三套分类逻辑。

## 6. 当前代码基线与实施注意事项

截至 2026-07-22，项目现状如下：

- `src/routes/docs.tsx` 已提供 `/docs` 首页，只加载 `src/content/docs/*.mdx` 中的扁平首页文件。
- `src/content/docs/index.mdx` 和 `index.zh.mdx` 仍是“完整文档树迁移前”的临时入口。
- `src/routes/docs/$slug.tsx` 与 `src/routes/docs/$slug/$.tsx` 已占住详情 URL，但目前只显示迁移占位页。
- `/api/docs/search` 当前索引整个 `src/content`，未限定 `/docs`，也未按语言过滤。
- sitemap 当前只收录 `/docs`，未自动收录详情页。
- 网站 Header / Footer 中的教程入口仍需核对是否指向飞书外链。
- `/xiaohongshu/*` 与 `/douyin/*` 继续承担营销和平台 SEO 意图；教程站不可复制这些页面的营销正文。

## 8. 上线 Definition of Done

### 信息架构

- [ ] 侧边栏只有一条内容生产主线、一个品牌分支和一个参考区。
- [ ] 不存在“按身份 / 按目的 / 能力库”三套并列导航。
- [ ] 每个能力只拥有一个正文或一个明确页内章节。
- [ ] 没有为了目录对称创建内容单薄的概览页。

### 内容

- [ ] 所有正文页都有运营者视角方法卡。
- [ ] 所有正文页明确产品位置、输入、输出、限制和下一步。
- [ ] 300 条、去重、分批保存、500 条分段同步等规则与当前版本一致。
- [ ] 研究档案分享明确只读、可停止以及不包含原始素材。
- [ ] Agent 自动化只以未来愿景出现。

### 技术与体验

- [ ] `/docs` 首页和全部详情 URL 均可直接刷新访问。
- [ ] 侧边栏、移动抽屉、页内目录、搜索和前后页导航可用。
- [ ] 搜索只返回当前语言下的文档结果。
- [ ] canonical、hreflang、sitemap、`llms-full.txt` 包含正式文档页。
- [ ] 旧飞书教程和现有占位 URL 有明确迁移或重定向策略。
- [ ] `pnpm build` 通过，无断链和重复 slug。

### 人工验收路线

```text
博主 / OPC：
安装 → 采集样本与逐字稿 → 建立并监控对标 → 拆解爆款 → 扩展选题 → 生成稿件 → 同步飞书 → 导入 AI 知识库

品牌 / 企业：
完成内容生产主线 → 采集评论 → 扫描舆情 → 识别并筛选线索 → 导出或同步客资
```

任何一个关键动作如果需要用户离开 `/docs` 去猜下一步，均视为尚未完成。

## 9. 实施期间不得重新引入的结构

- 不把“采集与素材 / AI 工作台 / 线索与客资 / 导出与同步”重新作为四个并列主能力域。
- 不把“人群路线 / 目的入口 / 能力库”重新作为三个侧边栏一级栏目。
- 不按小红书、抖音复制两套教程树；平台差异写在同一能力页中，必要时使用页内 Tab 或差异章节。
- 不创建 V0.2.0 专属教程目录；更新日志只汇总并深链 canonical 正文。
- 不把“创作风格”“9 个延伸选题”“300 条”“500 条”拆成薄页面。
- 不因为能力被多个场景引用，就复制操作步骤。
- 不将北极星愿景写成已经可以操作的 Agent 教程。

最终判断标准只有一个：

> 侧边栏负责告诉用户下一步做什么；正文页负责把一个能力讲清楚；首页和索引负责把不同入口带到同一份正文。
