# 生产切流配置差距清单

更新时间：2026-06-30 08:54 CST

## 当前结论

- 生产主域 `https://mediaclaw.app` 仍由旧 Worker `mediaclaw-web` 服务，响应头包含 `x-opennext: 1` / `x-powered-by: Next.js`。
- 新 Worker 的 preview 和 staging 已证明公开页、SSR、noindex、基础业务接口和 P2 流程可运行；但当前 staging 使用的是 preview D1，不承载旧站生产数据。
- 旧站生产数据库是 PostgreSQL/Neon，不是 D1；库内已有真实用户、订单、积分、激活码、福利和分销数据。因此不能把当前空 D1 直接切到主域。
- 新仓库的 PostgreSQL schema 不是旧生产库的纯超集。直接让新 Worker 连接旧库会有缺表/缺列/字段语义变化风险，必须先准备可审阅的生产兼容迁移或代码兼容层。
- 旧 Worker 没有 Cloudflare secret，敏感项主要写在旧项目 `wrangler.toml` vars。新 Worker 生产候选必须改用 Wrangler secrets / Hyperdrive / DB config，不能照搬明文 vars。


新仓库当前 `.env.production` 只有公开/基础键：

```text

```

生产候选至少需要补齐：

- `AUTH_SECRET`：Wrangler secret，必须与正式登录/session 策略一致。
- `CONFIG_ENCRYPTION_KEY`：Wrangler secret；一旦生产 config 表存了加密 secret，后续必须稳定。
- 数据库：建议通过 Hyperdrive 绑定旧 Neon，而不是把 `DATABASE_URL` 明文放进 vars。
- `LICENSE_INTERNAL_TOKEN`：Wrangler secret，用于插件内部消费/修复接口；未设置时会回落到 `AUTH_SECRET`，不建议生产依赖回落。
- Zpay：`ZPAY_PID`、`ZPAY_PKEY` 走 Wrangler secret 或 DB config，且需要真实 notify 验证。
- R2：新代码实际读取 admin config 的 `r2_*` 键；旧 env 的 `R2_*` 需要迁成 DB config 的 `r2_access_key`、`r2_secret_key`、`r2_bucket_name`、`r2_upload_path`、`r2_endpoint`、`r2_domain`。
- AI：新代码支持 `chat_ai_provider`、`openrouter_*`、`kimi_*`、`deepseek_*` 等；旧生产 config 表没有 AI provider key，需要在候选环境补录后测试。

## 推荐切流方案

### 方案 A：PostgreSQL/Hyperdrive 生产候选

推荐作为主线。

1. 新建 MediaClaw 专用 Hyperdrive，连接旧生产 Neon。
2. 准备一个独立的 `mediaclawweb-prod-candidate` Worker，不配置 `mediaclaw.app` route。
3. 将 `DATABASE_PROVIDER=postgresql` 烘进候选 Worker，`HYPERDRIVE` 作为运行时连接，`AUTH_SECRET` / `CONFIG_ENCRYPTION_KEY` / Zpay / License token 走 Wrangler secrets。
4. 在候选 Worker 上先跑只读公开页和鉴权接口，再跑受控业务 smoke。
5. 对旧生产 DB 先产出可审阅 PostgreSQL 兼容 SQL，只做 additive / backfill，不直接执行。
6. 兼容 SQL 通过 review 后，短窗口执行，随后候选 Worker 复测。

优点：最大程度保留旧站生产数据和登录/订单/积分连续性。缺点：必须处理 schema 兼容。

### 方案 B：迁旧 Postgres 到新 D1

不推荐作为第一选择。

需要导出旧 Postgres、做类型转换、处理外键/索引/时间戳/JSON、暂停写入或建立短期冻结窗口，并验证支付/积分/激活码一致性。当前已有真实订单和积分数据，直接迁 D1 的风险高于 Hyperdrive 承接。

## 主域切换前硬门禁

以下全部通过后再切 `mediaclaw.app`：

- 生产 DB 方案确认：Hyperdrive 承接旧 Neon，或完成旧 Postgres -> 新 D1 数据迁移。当前 preview D1 不可用于主域。
- PostgreSQL 兼容 SQL 已审阅并执行，至少覆盖新代码缺表/缺列和分销字段语义迁移。
- `AUTH_SECRET`、`CONFIG_ENCRYPTION_KEY`、`LICENSE_INTERNAL_TOKEN`、Zpay、R2、AI provider 已在候选环境设置，并只输出 secret 名称不输出值。
- 候选 Worker 使用 `https://mediaclaw.app` 烘焙 URL 重新构建，确认 canonical/hreflang/sitemap/支付 callback base 都是主域。
- 候选 Worker 通过：
  - `pnpm verify:web`
  - `pnpm cf:build`
  - `MEDIACLAW_E2E_BASE_URL=<candidate-url> pnpm test:p2`
  - 公开页 URL 对照表 smoke
  - 登录、插件 validate/consume、Zpay notify、支付 callback、AI key test
- 旧 Worker 回滚路径保留：`mediaclaw-web` + 版本 `756c0a66-cc8f-4fa5-a649-4b0b3235c977`。

## 下一步执行清单

当前按人工验收要求暂停在 `mediaclawweb-preview` 阶段。人工检查通过前，不继续切主域或灰度 route。

人工检查之后：

1. 如果发现页面/功能问题，先回到新仓库修复并重新部署 preview。
2. 如果人工检查通过，再确认生产数据方案。当前 preview D1 不承载旧站生产数据，不能直接作为主域生产库。
3. 需要保留旧站生产数据时，优先使用已创建的 `mediaclawweb-prod-candidate` Hyperdrive 候选链路，或制定旧 PostgreSQL 到新生产库的数据迁移方案。
4. Review `docs/research/production-postgres-compat-draft.sql`。只有确认要让新 Worker 承接旧 PostgreSQL 时，才把末尾 `ROLLBACK` 改为 `COMMIT` 并在维护窗口执行。
5. 候选 Worker 必须通过公开页、登录、插件 validate/consume、Zpay notify、支付 callback、AI key test 和 P2 后，才进入主域切换。
6. 最后才改 Cloudflare route 切 `mediaclaw.app`，并保留旧 Worker 回滚路径。
