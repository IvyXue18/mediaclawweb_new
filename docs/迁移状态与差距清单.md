# MediaClaw TanStack 迁移状态与差距清单

更新时间：2026-06-30

## 当前结论

迁移当前暂停在 **Cloudflare preview 人工验收阶段**。旧项目 inventory 共有 128 个迁移目标路由，其中 84 个页面、44 个 API。当前 TanStack 工作区已经能构建、公开页 smoke 已能运行；按真实 TanStack 文件和等价动态路由计算，URL 覆盖已到 128/128。

当前用于人工检查的入口是 `https://mediaclawweb-preview.ycxue18.workers.dev`。preview Worker 未配置主域 `routes`，响应带 `X-Robots-Tag: noindex, nofollow`。生产主域 `https://mediaclaw.app` 仍由旧 Worker `mediaclaw-web` 服务，未切换。

这一阶段的目标是让人工逐页检查所有公开页面和核心业务入口：文案、首页视频/媒体位、移动端布局、登录、Zpay 前端交接、插件接口、AI key 测试入口等。人工检查通过前，不推进主域切换。

后续重点不再是“路由文件缺失”，而是人工 QA 发现的问题修复、旧站主题细节、移动端视觉、AI/chat 运行时行为、后台/用户中心交互、真实支付配置，以及生产数据承接方案。

这份文档用于防止把“页面能打开”误判为“全量复刻完成”。

## 人工检查之后还需要做什么

人工检查分两种结果处理：

1. 如果人工检查发现页面或功能问题：
   - 在新仓库修复对应页面、文案、样式或接口。
   - 跑对应的窄测试和必要的 `pnpm verify:web` / `pnpm cf:build`。
   - 重新部署到 `mediaclawweb-preview`。
   - 更新 `docs/research/preview-人工检查清单.md`，再继续人工复查。

2. 如果人工检查通过，准备正式切主域：
   - 先确认生产数据策略：不能直接用当前 preview D1 承接主域；需要选择“旧 PostgreSQL 通过 Hyperdrive 承接”或“旧 PostgreSQL 数据迁移到新生产库”。
   - 迁移/确认生产配置：`AUTH_SECRET`、`CONFIG_ENCRYPTION_KEY`、Zpay、License token、R2、Google OAuth、Analytics、AI provider 等。
   - 如果选择旧 PostgreSQL + Hyperdrive：review `docs/research/production-postgres-compat-draft.sql`，确认后再把最后的 `ROLLBACK` 改为 `COMMIT` 并在维护窗口执行。
   - 用无主域的候选 Worker 跑生产态 smoke：公开页、登录、插件 validate/consume、Zpay notify/payment callback、AI key test、P2。
   - 切主域前把 `VITE_APP_URL` / `AUTH_URL` 烘成 `https://mediaclaw.app`，重新构建部署。
   - 最后才改 Cloudflare route，把 `mediaclaw.app` 从旧 Worker 切到新 Worker，并保留旧站 Worker 快速回滚。
   - 切后 48 小时监控 Search Console、404、重定向、Cloudflare 5xx、GA/Plausible、支付/注册/下载/插件事件。
