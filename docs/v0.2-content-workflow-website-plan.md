# MediaClaw V0.2 官网内页与 SEO 架构方案

> 执行周期：下一周
> 核心定位：小红书与抖音自媒体内容工作流
> 方案依据：MediaClaw GSC、Bing Webmaster 真实搜索数据，以及 V0.2 已上线能力

## 1. 本次重构的结论

MediaClaw 官网不再按照“采集、分析、生成、监控”等孤立功能组织页面，也不再使用功能集合式表达。

V0.2 的官网统一围绕一条完整的自媒体内容工作流展开：

> 发现内容方向 → 研究账号与爆款 → 沉淀选题和内容风格 → 生成图文或视频稿 → 持续追踪与复盘

页面架构采用“平台优先、搜索意图分层”的方式：

1. 小红书和抖音各有一个平台 Hub，承接平台级宽泛需求，解释完整工作流。
2. 账号分析、爆款分析、选题库按照平台分别建页，承接用户实际带平台名的搜索。
3. 关键词下拉词、对标账号发现、低粉爆款、一篇内容拆解、舆情扫描等能力不单独建 SEO 页面，而是进入最匹配的需求页，成为工作流步骤。
4. 已有采集、评论、逐字稿、监控、去水印页面保留 URL 和核心搜索意图，仅增加与上下游工作流的连接。

最终新增 8 个页面：

```text
/xiaohongshu
/douyin

/xiaohongshu/account-analysis
/douyin/account-analysis

/xiaohongshu/viral-content-analysis
/douyin/viral-content-analysis

/xiaohongshu/topic-library
/douyin/topic-library
```

不新增根目录下的 `/account-analysis`、`/viral-content-analysis` 或 `/content-idea-library`。用户搜索通常带有平台名称，现有官网架构也已经形成 `/xiaohongshu/*` 与 `/douyin/*` 两套平台路径，继续沿用更有利于搜索意图匹配、内部链接和后续扩展。

### 2.3 V0.2 新需求的早期信号

当前账号分析、选题、低粉爆款、舆情等新意图尚未形成很大的可见查询量，但已经出现精准搜索：

- Bing 查询 `能分析抖音和小红书账号的工具`：3 次展现、1 次点击、平均排名 2。
- 对标/竞品相关查询：GSC 4 次展现；Bing 11 次展现、5 次点击。
- 爆款相关查询：Bing 7 次展现、2 次点击。
- 选题相关查询：Bing 11 次展现、1 次点击，包含“小红书选题平台”“小红书找选题用哪个平台”等明确意图。
- 品牌舆情相关查询：Bing 2 次展现，尚无点击。

同时，已有内容页已经获得页面级曝光：

- 低粉爆款文章：GSC 合计约 245 次展现，但 0 点击。
- 选题库文章：GSC 合计约 62 次展现；Bing 10 次展现、1 次点击。
- 找对标账号文章：GSC 合计约 45 次展现，0 点击。
- 品牌舆情文章：GSC 仅 1 次展现。

因此，本轮不应把每一个 V0.2 功能都拆成独立页面。更合理的方式是把早期、相近意图组合成少数高完整度页面：

- “自动找对标账号”与“账号深度分析”组合为账号分析页。
- “低粉爆款发现”与“单篇/单条内容拆解”组合为爆款分析页。
- 关键词、评论、对标账号、爆款和舆情产生的内容方向统一沉淀到选题库页。
- 舆情扫描先作为“发现方向”和“持续复盘”的能力，不单独建页。

> 数据解释注意：GSC 会隐藏一部分低量查询，因此关键词页的页面展现明显高于公开查询行之和。页面级展现可证明该方向已被搜索，但不能据此虚构具体关键词的搜索量。

### 3.1 导航原则

顶部导航以平台为入口，不把所有功能平铺成一个大列表：

```text
小红书内容工作流 | 抖音内容工作流 | 生态 | 资源 | 下载 | 定价
```

悬浮菜单内部按照工作流阶段分组，而不是按技术功能分组：

1. 发现方向：关键词洞察、评论研究、舆情线索。
2. 研究样本：内容采集、账号分析、爆款分析、逐字稿与图文提取。
3. 沉淀资产：选题库、内容风格、研究报告。
4. 生成内容：图文生成、视频稿生成等 V0.2 创作能力。
5. 持续复盘：竞品监控、评论反馈、飞书同步。

导航可以展示具体功能名称，但平台 Hub 的核心表达必须是“完整内容工作流”，不能让用户感觉只是多个工具的集合。

## 4. 两个平台 Hub 的页面方案

平台 Hub 负责回答三个问题：

1. MediaClaw 能帮这个平台的创作者完成什么完整工作？
2. 用户应该从哪一个步骤开始？
3. 每个步骤如何衔接成可持续的内容生产系统？

### 4.1 `/xiaohongshu`：小红书自媒体内容工作流

#### 搜索定位

- 主关键词：小红书运营工具、小红书自媒体工具、小红书内容运营
- 次关键词：小红书内容分析工具、小红书创作工具、小红书运营软件
- 用户目的：寻找能覆盖小红书研究、选题、创作和复盘的完整解决方案

#### 建议 TDK 与 H1

- 中文 Title：`小红书自媒体内容工作流｜从内容研究、选题到创作 | MediaClaw`
- 中文 H1：`一套完整的小红书自媒体内容工作流`
- 中文 Description：`围绕小红书创作，把搜索需求、对标账号、爆款笔记和评论反馈变成可执行选题，再按研究出的内容风格生成图文或视频稿，并持续追踪发布后的内容与竞品变化。`
- 英文 Title：`Xiaohongshu Content Workflow: Research, Ideas & Creation | MediaClaw`
- 英文 H1：`A complete content workflow for Xiaohongshu creators`

#### 页面首屏表达

主文案：

> 从“今天发什么”，到“为什么这样做、怎样持续做”。
> 用一套工作流完成小红书内容研究、账号拆解、选题沉淀、图文创作和持续复盘。

首屏 CTA：

- 主 CTA：`开始小红书内容研究`
- 次 CTA：`查看完整工作流`

#### 页面模块顺序

1. Hero：完整工作流价值，不展示功能墙。
2. 五阶段工作流总览：方向、样本、资产、创作、复盘。
3. 发现内容方向：关键词搜索下拉词、评论问题、舆情变化。

5. 建立选题与风格资产：把证据保存为选题、风格卡和研究报告。
6. 生成小红书内容：根据选题和已研究的表达方式生成图文或视频稿。
7. 发布后持续复盘：监控对标账号、评论反馈和内容变化。
8. 典型工作流模板：新账号冷启动、矩阵号选题、品牌内容研究。
9. 相关能力入口：仅作为工作流节点卡片出现。
10. FAQ：回答数据来源、支持范围、是否需要登录平台、合规边界等问题。

## 5. 新增需求页方案

### 5.1 小红书账号分析页

- URL：`/xiaohongshu/account-analysis`
- Title：`小红书账号分析工具｜自动找对标账号、拆解选题与内容风格`
- H1：`从找到小红书对标账号，到看清它为什么持续出爆款`
- 主关键词：小红书账号分析、小红书对标账号
- 次关键词：小红书竞品账号分析、小红书账号数据分析、小红书博主分析
- 页面目的：承接“找谁学”和“这个账号为什么做得好”两个连续问题

#### 组合能力

1. 输入行业词、产品词或种子账号。
2. 自动发现相关对标账号。
3. 按头部、腰部、低粉高互动等条件筛选。
4. 批量采集账号历史笔记和表现数据。
5. 分析定位、选题结构、标题、封面、内容形式和更新节奏。
6. 识别持续有效的内容风格，而不是只看单篇爆款。
7. 把发现保存为选题、风格参考或监控对象。

#### 核心转化路径

`找到对标账号 → 分析账号 → 查看代表爆款 → 保存选题/风格 → 加入竞品监控`

页面要链接到：关键词洞察、笔记采集、爆款分析、选题库、竞品监控。

### 5.2 抖音账号分析页

- URL：`/douyin/account-analysis`
- Title：`抖音账号分析工具｜找对标账号、拆解爆款视频与内容风格`
- H1：`从找到抖音对标账号，到拆清它的爆款视频规律`
- 主关键词：抖音账号分析、抖音对标账号
- 次关键词：抖音竞品账号分析、抖音达人分析、抖音账号数据分析

#### 平台差异

除账号定位、选题和更新频率外，重点展示：

- 视频开头钩子。
- 视频时长分布。
- 逐字稿和脚本结构。
- 节奏、转折和互动设计。
- 不同视频形式的稳定表现。

核心转化路径与小红书相同，但内容样本和分析报告必须是视频维度。

### 5.3 小红书爆款分析页

- URL：`/xiaohongshu/viral-content-analysis`
- Title：`小红书爆款分析｜找低粉爆款并拆解爆款笔记`
- H1：`找到可复制的小红书低粉爆款，再拆清它为什么会爆`
- 主关键词：小红书爆款分析、小红书低粉爆款
- 次关键词：小红书爆款笔记分析、小红书爆款拆解、小红书爆款内容

#### 组合能力

1. 按关键词或赛道批量发现爆款笔记。
2. 用粉丝量、互动量和发布时间识别低粉爆款。
3. 提取标题、正文、图片文字、标签和评论。
4. 拆解选题、开头、信息结构、情绪价值、视觉表达和互动触发点。
5. 基于一个有效样本扩展多个可执行选题。
6. 将结果保存到选题库或内容风格资产。

核心转化路径：

`发现低粉爆款 → 拆解单篇内容 → 判断可复制部分 → 扩展选题 → 进入创作`

### 5.4 抖音爆款分析页

- URL：`/douyin/viral-content-analysis`
- Title：`抖音爆款分析｜找低粉爆款并拆解爆款视频`

- 次关键词：抖音爆款视频分析、抖音爆款拆解、短视频爆款分析

#### 平台差异

重点展示：

- 视频开头 3 秒钩子。
- 完整逐字稿与脚本段落。
- 信息密度、转折和节奏。
- 画面/口播形式。
- 评论中的共鸣点、疑问和反对意见。
- 从一个视频生成系列化选题与新脚本的过程。

### 5.5 小红书选题库页

- URL：`/xiaohongshu/topic-library`
- Title：`小红书选题库｜从关键词、评论和爆款持续找到好选题`
- H1：`把零散灵感变成持续更新的小红书选题系统`
- 主关键词：小红书选题库、小红书选题工具
- 次关键词：小红书怎么找选题、小红书选题平台、小红书内容选题

#### 页面核心不是“收藏列表”，而是选题形成过程

选题来源包括：

- 搜索关键词和下拉词。
- 用户评论中的问题、需求和情绪。

## 8. 本轮不单独建页的能力

| 能力                  | 归属页面                         | 原因                                                     |
| --------------------- | -------------------------------- | -------------------------------------------------------- |
| 长尾关键词            | 平台关键词洞察页                 | 与搜索词挖掘同一意图                                     |

| 低粉爆款              | 平台爆款分析页                   | 是筛选方式，不是独立最终目的                             |

1. GSC/Bing 出现持续、明确且与现有页面不同的查询簇。
2. 页面能提供独立输入、独立结果和独立转化目标。
3. 可以写出足够的平台专属内容，而不是复用同一套说明。
4. 拆分不会与现有页面产生关键词竞争。

## 9. 页面内容设计规范

### 9.1 所有新增页面统一回答六件事

1. 用户当前遇到的具体问题是什么。
2. MediaClaw 如何把多个能力串成一条工作流。
3. 用户需要提供什么输入。
4. 系统会完成哪些分析步骤。
5. 最终产出什么可继续使用的内容资产。
6. 下一步能进入哪个工作流节点。

### 9.2 页面不应出现的表达

- 连续堆叠十几个功能名称。
- “一站式”“全能”等没有证据的泛化口号。
- 只说 AI 分析，不展示输入、过程和输出。
- 把采集数据当作用户最终价值。
- 小红书与抖音只替换平台名称，案例和字段完全一致。
- 使用功能集合式定位作为导航名称或首屏文案。

### 9.3 建议使用的体系化表达

- `从搜索需求到可执行选题`
- `从对标账号到可复用的内容规律`
- `从爆款样本到系列化内容方向`
- `把研究结果沉淀成长期内容资产`
- `让每次发布的数据回到下一轮选题`
- `形成研究、选题、创作、复盘的完整闭环`

### 9.4 每页基础 SEO 要求

- 唯一的 Title、Description 和 H1。
- 中文与英文版本均有平台专属内容。
- 正确 canonical 与中英文 hreflang。
- BreadcrumbList 结构化数据。
- 产品/软件页根据实际内容增加 SoftwareApplication 或 WebApplication 数据。
- FAQ 只有在页面真实展示问答时才输出 FAQ 结构化数据。
- 至少 3 个正文上下文内链，不只依赖页脚。
- 图片 alt 描述实际界面或结果，不堆关键词。
- 新路由进入 sitemap、`llms.txt` 和 `llms-full.txt`。

## 10. 内部链接工作流

每个平台内部形成相同但内容不同的闭环：

```text
平台 Hub
  ↓
关键词洞察 ──→ 账号分析 ──→ 爆款分析
     │              │             │
     └──────────────┴─────────────┘
                    ↓
                  选题库
                    ↓
              图文/视频稿生成
                    ↓
          评论反馈 + 竞品监控复盘
                    ↓
                下一轮选题
```

具体规则：

1. 平台 Hub 链接全部核心页面。
2. 关键词页链接账号分析、爆款分析和选题库。
3. 账号分析页链接采集、爆款分析、选题库和监控。
4. 爆款分析页链接逐字稿/图文提取、评论和选题库。
5. 选题库页反向链接关键词、账号、爆款和评论页面，并进入创作流程。
6. 监控页链接账号分析和选题库，完成闭环。
7. 博客只链接与当前段落直接相关的产品页，避免统一堆在文末。
