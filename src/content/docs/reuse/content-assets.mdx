内容资产不是“存了一堆文件”，而是以后能找到、能看懂来源、能被人或 Agent 继续使用的材料。建议把社媒虾 MediaClaw 中的资产分为四层，并保留它们之间的关系。

## 四层内容资产

| 层级              | 包含什么                                                             | 主要价值                           |
| ----------------- | -------------------------------------------------------------------- | ---------------------------------- |
| 1. 原始数据资产   | 作品与账号链接、标题、正文、互动数据、评论、图片、视频、采集时间     | 保留可追溯的事实与原始样本         |
| 2. 分析与知识资产 | 图片文案、视频逐字稿、账号分析、单篇拆解、关键词结论、账号风格、选题 | 把原始样本变成可比较、可调用的知识 |
| 3. 创作资产       | 创作简报、大纲、所用证据、账号风格、图文稿、视频稿、版本记录         | 让内容可以协作、修改和再生产       |
| 4. 发布与复盘资产 | 发布链接、发布时间、平台表现、评论反馈、复盘结论                     | 用真实结果修正下一轮研究和创作     |

只保留第 1 层，下一次仍要重新分析；只保留第 3 层，又会失去稿件为什么这样写的依据。四层连起来，才是一套可以持续生长的资产。

## 当前有哪些沉淀位置

### 插件本地数据池

保存采集记录与任务进度，适合继续补采、筛选、导出和让 Agent 直接读取。它属于浏览器本地数据，清理扩展数据、卸载扩展或更换设备都可能影响记录。

### AI 工作台

保存账号分析、单篇拆解、账号风格、选题和生成内容。它们是分析后的资产，不只是一次性结果；Agent 可以按类型查找并读取完整对象，用于新的研究和创作。

### 本地导出文件

- **CSV**：适合统计、筛选、合并和建立索引。
- **Markdown**：适合保留正文与分析上下文，放入本地知识库或交给 Agent 阅读。
- **图片 ZIP**：适合视觉复盘和素材归档；是否可用于发布取决于授权。

具体操作见[导出数据到本地](/docs/collect/export-local)。

### 飞书多维表格

适合多人协作、状态管理、负责人分配和按项目建立视图。团队可以把研究结论、创作状态与发布结果写回同一条记录。具体操作见[同步到飞书多维表格](/docs/collect/feishu-sync)。

### 你自己的知识库

品牌手册、产品事实、客户案例、采访、个人观点和历史内容通常不在 MediaClaw 内。可以把它们保存在 Agent 客户端能读取的本地项目或知识库中，再与 MediaClaw 资产一起使用。

## Agent 可以直接读取哪些 MediaClaw 资产

| 来源           | 可读取资产                                                   | 说明                                                     |
| -------------- | ------------------------------------------------------------ | -------------------------------------------------------- |
| 本地数据池     | 原始采集记录、正文、评论、互动、图片文案、逐字稿等已保存字段 | 读取已有内容不需要重复采集                               |
| 本地 AI 工作台 | 单篇拆解、账号分析、账号风格、选题、已生成内容               | 适合继续选题、比较和创作                                 |
| 远端工作台     | 当前账号下可用的拆解、分析、风格和生成资产                   | 需要有效会员与当前连接权限                               |
| 外部知识库     | 你授权给 Agent 客户端的品牌资料、文件和项目内容              | 不是 MediaClaw 自动上传；读取范围由 Agent 客户端权限决定 |

  可以读取”不等于“资料已经自动备份”。浏览器本地资产仍应按重要程度导出或同步；外部知识库也只有在你明确授权相应目录或连接后，Agent
  才能使用。

## 每条资产建议保留的字段

- 唯一编号、资产类型和当前版本。
- 来源平台、原始链接、作者和采集时间。
- 所属项目、账号、关键词和内容主题。
- 原始事实、分析结论与人工判断的区分。
- 结论所依据的样本编号或链接。
- 使用权限、引用限制与事实核验状态。
- 创作任务、使用的风格和稿件版本。
- 发布链接、表现数据、复盘结论和最后更新时间。

## 建议的资产闭环

1. **采集**：保存原始链接、时间和平台字段。
2. **补齐**：按需要补采正文、评论、图片文案和逐字稿。
3. **分析**：产出账号、单篇、关键词和用户需求结论，并保留证据。
4. **创作**：从结论进入选题与创作简报，再生成和修改稿件。
5. **发布**：记录最终版本和发布链接。
6. **复盘**：写回表现、评论反馈、有效机制和失效判断。
7. **再利用**：下一轮先检索已有资产，命中后读取完整记录，缺什么再补采。

## 避免资产越积越乱

- 不把原始样本、分析结论和最终稿混在同一个文本字段里。
- 同一个资产更新时保留版本或更新时间，不复制出多个无法判断新旧的文件。
- 每条分析结论至少关联一个来源；没有证据的内容标记为假设。
- 对数据、价格和规则等会变化的事实记录核验日期。
- 对无授权素材只保存研究链接和特征描述，不复制进发布素材库。
- 每周清理重复和不可用样本，每月复核高频选题与账号风格是否仍然有效。
