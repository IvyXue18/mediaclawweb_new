## 这里说的Agent是什么

Agent 指**能自己调用工具、连着做完一串操作的 AI 对话工具**。它不只是陪你聊天，还能按你的一句话去打开软件、读写文件、执行任务。目前社媒虾支持接进这几个：

- **Codex**（已支持）
- **WorkBuddy**（已支持）
- **豆包工作**（已支持）

把社媒虾接进这类工具之后（怎么接见[安装、配对与升级](/docs/agent/setup)），你就可以在对话框里用大白话指挥它，比如直接发一句：

```plaintext
帮我分析这个小红书账号：<主页链接>，先告诉我要采多少条再动手。
```

它会自己去调用社媒虾采集数据、整理，再把结论讲给你——你不用一个个去点插件里的按钮。

## 接入之后，谁负责什么

一次任务里有三方：

| 谁                       | 负责的事                                                                       |
| ------------------------ | ------------------------------------------------------------------------------ |
| **社媒虾**               | 去小红书、抖音采集数据、清洗、抽样、做客观统计，并提供一套现成的研究和写作方法 |
| **你的 AI 对话工具**     | 读懂你的要求，照着这套方法做分析、判断和写稿                                   |
| **你自己的资料**（可选） | 提供你的业务事实、过往表达和不能碰的红线，让稿子像你写的                       |

三方少一方，结果就会打折：只有社媒虾，是一堆数据没有结论；只有 AI 工具，是没有真实样本的空谈；没有你的资料，写出来的东西不像你、也没有你的业务。

## 它干活的固定顺序

它不是拿到问题就瞎猜。每次任务内部都按固定顺序走，知道这个顺序，它的很多做法就不奇怪了：

1. **先查连接是否正常**，需要时提示你升级接入包。
2. **按你的意图选一套研究方法**。社媒虾为常见任务（关键词趋势、长尾需求、账号策略、账号近期爆款、找对标账号、拆解单篇、选题、写作任务书、成稿、风格适配）各准备了一份写好的方法，它照着做。
3. **先查有没有现成结果，再决定要不要新采**。顺序是：插件本地已有的分析 → 云端工作台 → 本地采集记录 → 都没有才新采。所以你说「分析这个账号」，它可能直接回答而不重新采——这是在省你的时间和额度，不是偷懒。
4. **只补缺的那部分**。已经采过作品列表、只缺个别详情，它就只补详情，不会清空重来。
5. **先分析再写**。它会先讲清楚：现在有哪些证据、哪些说法反复出现、读者需求有没有互相打架、这类内容为什么能火——然后才进入选题和写稿。
6. **交付前自己过一遍**：核心结论有没有证据、有没有把猜测写成事实、和参考作品像不像得过头、有没有把别人的经历写成你的。

<Callout type="note">
  它会分清楚**哪些是查到的事实、哪些是它的推测、哪些还不知道**。一个例子它只当个案，要看到至少三个互相独立的例子都指向同一个结论、又没有明显反例，它才会说这是普遍规律。所以你会看到它说「这条还不太确定」或「这需要更多样本」——这是方法要求，不是敷衍。
</Callout>

## 它会停下来问你的几件事

这五件事必须你点头，它不能替你决定：

| 动作       | 它会先给你什么                                                           | 你确认之后                                              |
| ---------- | ------------------------------------------------------------------------ | ------------------------------------------------------- |
| 采集账号   | 一份采集方案：目标、字段、范围、分几批、风险提示（普通／黄色／红色三级） | 才开始执行，且只执行方案里写明的批次                    |
| 视频逐字稿 | 一份报价：每条预计多少积分、总额、余额、有效期                           | 才开始提取；已经提过的项目不重复扣分                    |
| 批量补详情 | 这次要补的范围                                                           | 才进详情页补采                                          |
| 清理数据   | 影响范围：多少条记录、评论、逐字稿，预计能腾出多少空间                   | 才执行删除                                              |
| 评论私信   | 一份收件人名单和话术                                                     | **还要你回插件的「采集与获客 → 评论获客」里做最终确认** |

## 会很消耗 Token 吗

<Callout type="note">
  这里说的 Token 是你的 Agent 宿主（Codex、WorkBuddy
  等）消耗的模型额度，和在社媒虾里提取逐字稿要花的**积分**是两回事。
</Callout>

用 Agent 指挥社媒虾，本身就是相对省 Token 的做法。它不用自己一页页打开、点击、翻页、逐屏读取——采集和提取交给插件执行，插件只把整理好的结构化结果交回来给它分析。

一次任务里，真正消耗宿主模型 Token 的是三件事：

| 环节       | 在做什么                                     |
| ---------- | -------------------------------------------- |
| 理解与规划 | 读懂你的要求，选定一套研究方法，安排分几步走 |
| 调用与读取 | 发起插件调用，再读回采集和分析结果           |
| 分析与写作 | 对结果做统计、归类、判断，最后成稿           |

插件在后台采集、翻页、等平台限频冷却的那段时间，本身一般不额外花 Token。所以一个任务跑了十几分钟，不等于十几分钟都在烧 Token。复杂任务确实更贵，但贵在数据量更大、要分析的步骤更多，不在于插件跑了多久。

它还会主动压掉一部分开销：[固定顺序](#它干活的固定顺序)里的"先复用、再新采"省掉重复采集；较大的返回会先给摘要和预览，需要细节时才分页读取，不会一次把无关内容塞进上下文。

以下情况仍会用掉一些 Token：频繁查询任务进度或反复确认连接、遇到登录失效和验证码这类异常时的多轮来回、把大量原始数据（例如上千条评论原文）读进来再分析。具体消耗还取决于你用的模型、任务复杂度和返回的数据量。

<Callout type="tip">
  **优势**：比起让 Agent
  自己开浏览器、一步步点页面，社媒虾把整批采集一次接管过去，只交回需要的数据和结论，省下的正是那些重复点击、翻页、读取会烧掉的
  Token。你付的 Token 花在"理解需求"和"分析结果"上，不花在"操作浏览器"上。
</Callout>
